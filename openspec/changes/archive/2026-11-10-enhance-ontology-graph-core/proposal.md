# Proposal

## Why

V1.0.0 已经能把 `.ttl` / `.owl` / `.rdf` / `.jsonld` / `.nt` / `.n3` 文件渲染成可交互的只读图谱，但当前实现仍是"能看的基础文件预览器"，离"可信、可探索的本体工具"有明显差距：

- **身份不可信**：相对 IRI 用显示文件名推导 HTML 式 Base IRI（`src/rdf-parse.js:119-127`），同一基名的不同文件会得到相同资源身份，详情面板展示的 IRI 可能与真实资源地址不符。
- **状态不可信**：解析器的三元组截断标识只存在于构建器内部（`src/rdf-parse.js:144`），`finish()` 未输出该字段（`:206-219`），`src/main.js:229/258` 读取的 `parsed.stats.truncated` 永不存在，截断徽标不可达；建图的节点/字面量截断也没有结构化地进入视图。
- **入口不一致**：better-sidebar 打开 0 字节文件会永久停在"正在读取"（`src/main.js:384`），DSH 原生预览却正确进入 empty（`:357-372`）。
- **语义损失无提示，且已有静默丢数据**：TriG 命名图、N-Quads 图名、JSON-LD 的部分关键词、RDF/XML 未完整支持的结构被丢弃时没有诊断；其中 JSON-LD 顶层 `@graph` 与兄弟键并存时兄弟键被静默丢弃（`src/rdf-parse.js:2213-2217`），仓库自带 `examples/courses.jsonld:12-15` 实测已丢 2 条三元组；`@container` 的 `@list` 与基线规格要求不符（`src/rdf-parse.js:2310-2315` 先于 `2342-2346`）。
- **大文件不可用**：解析、建图与 320 次迭代布局全部同步跑在主线程（`src/main.js:221-234`、`src/graph-view.js:228-230`），没有可取消任务；预算只有三元组/节点上限，没有边数与 SVG 元素预算，1500 节点高密度图会产生数万 DOM 元素且每次悬停整图重渲染。
- **探索能力缺失**：只有"全图"与"单跳聚焦"两种视图（`src/graph-view.js:242-245`），没有节点/关系过滤、没有可调 1–5 跳邻域、详情没有邻接关系列表，搜索只能跳第一个命中。

这些问题共同决定了本次变更的动机：把查看器从"文件预览"升级为"可判断、可探索、在大图上仍可用的本体探索工具"，同时显式保留其轻量、零依赖、只读的定位。

## What Changes

### 模块 A：解析准确性与边界修复

- 相对 IRI 的 Base IRI 改为由**真实资源地址**推导（DSH 原生预览的 `resourceAddress`、better-sidebar 的 `path`），显示文件名只用于标题；无法获得真实地址时不再伪造 `file:///` 身份，而是按"无 Base"降级并给出诊断。节点 IRI 与标签的展示语义随之更准确。
- 解析器输出新增**结构化截断信息**（是否截断、原因、保留数量、原始/上限），并贯通到图模型与视图；截断徽标、计数与详情中的"已截断"提示变为可达且准确。
- 统一"读取中 / 读取完成但为空 / 读取失败"三种状态，DSH 原生预览与 better-sidebar 两个入口行为一致。
- 为已被静默丢弃的格式语义增加**分类诊断**：TriG 命名图、N-Quads 图名、JSON-LD 不支持关键词与反向关系、RDF/XML 未完整支持的结构。只修明确错误、补诊断与能力边界标识，不实现完整标准。明确修复两处已确认的 JSON-LD 错误：顶层 `@graph` 兄弟键静默丢失、term 级 `@container:"@list"` 未按列表展开。OWL 复杂限制表达式经审计由现有通用映射保留为三元组结构，本次不新增 OWL 专用推理语义，只用回归测试固化保留能力并在文档声明边界。
- 为异常输入增加**资源上限与恢复保障**：字面量长度、诊断条数、嵌套深度、集合/空白节点规模等明确上限与针对性回归测试，避免警告洪泛（当前 5000 条错误会全部渲染进提示条）、栈溢出吞成单条错误以及超大标签进入渲染。

### 模块 B：大文件与图谱性能

- 解析、建图与布局改为**可取消、可丢弃过期结果**的任务模型；以 Web Worker 为首选路线，但先做真实 DSH 运行时可行性验证，不适配时退化为分片/让步计算，两条路线都保持确定性布局。
- 拆开三层预算：**解析三元组预算**、**图模型节点预算**、**SVG 绘制边/元素预算**；对超预算图谱给出明确、可读的截断提示与当前显示规模。
- 建立**性能基准**（小型/中型/接近上限/高密度/异常输入五类夹具，分阶段计时），先测量再定数字；本轮不写入未经测量的性能目标。

### 模块 C：节点与关系过滤

- 按节点类型（类/属性/个体/空白节点/外部引用）、关系类型（常用语义谓词 + 本体自定义谓词）与关系方向（入边/出边/双向）过滤当前显示。
- 实时显示过滤条件与过滤后的节点/边数量，支持清除过滤并恢复完整视图；过滤只影响展示，不修改 RDF 原始数据或图模型。

### 模块 D：多跳邻域探索

- 在现有单跳聚焦基础上提供 1–5 跳探索，支持入边/出边/双向展开，可与关系过滤组合。
- 高连接度节点按需展开或受预算限制，避免一次拉入过多内容；可一键回到完整视图；搜索、选择、详情与多跳模式保持协调。

### 模块 E：节点详情增强

- 详情面板展示完整 IRI 与可读标签、全部 `rdf:type` 与已保留字面量属性、按关系类型组织并可折叠的入边/出边列表，支持点击关联节点在图内定位。
- 对被截断的字面量、节点或边明确提示；为后续源文件定位预留数据结构（本次不实现跨文件定位）。

### 模块 F：交互体验与 UI 优化

- 搜索改为"查看匹配结果并选择目标节点"；工具栏重排以减少对图谱可视面积的挤占；优化窄侧栏/小窗口布局与加载、失败、截断、无结果状态提示。
- 保留明暗主题自适应、中英双语、缩放/拖拽/重新布局/适配视图/节点高亮等既有能力；改善键盘交互与基础可访问性。视觉上做增量优化，不重新设计视觉体系。

## Capabilities

### New Capabilities

无新增 capability。本 Change 的六组行为都能归入既有能力边界，按现有 spec 组织以 delta 形式修改，避免新增宽泛 catch-all capability。

### Modified Capabilities

- `rdf-parsing`：新增 Base IRI 来源契约、结构化截断字段、语义损失诊断分类与资源上限；修正"文件名为 Base"的隐含行为。
- `graph-model`：新增可取消/可丢弃结果的计算契约所依赖的稳定输入输出、绘制预算（边/元素）与截断元数据、过滤投影、1–5 跳探索与展开预算、详情连接分组数据、源位置预留字段。
- `graph-view`：新增过滤 UI 与计数、多跳控件、详情邻接列表与折叠、搜索结果选择、状态/截断提示、工具栏与窄屏布局、键盘与可访问性；保持既有交互能力。
- `dsh-integration`：统一原生预览与 better-sidebar 的读取中/为空/失败状态语义；明确后台计算不得改变 Client 模块加载与注册契约。
- `localization-and-theme`：新增文案的 key 覆盖机制扩展到拆分后的 UI 模块，新增动态 key 家族纳入检查；主题令牌约束适用于新增控件。
- `build-and-verification`：构建脚本支持新增 UI 模块与（若采用）内嵌 Worker 源；新增性能基准命令与分阶段测试；真实 DSH 页面验收要求覆盖新增交互。

## Impact

- **源码**：`src/rdf-parse.js`、`src/graph-model.js`、`src/graph-view.js`、`src/main.js`；为控制单文件体积与可维护性，可能按既有拼接顺序新增少量 UI/辅助源文件（需同步 `build/build.mjs` 的 `MODULES`）。
- **构建产物**：`client.js` 由 `npm run build` 重新生成并随源码提交；不得手改。
- **构建与脚本**：`build/build.mjs`（模块清单/可能的 Worker 源内嵌）、`scripts/check-i18n.mjs`（扫描范围）、新增 `scripts/bench.mjs` 与 `package.json` scripts。
- **测试**：`tests/parse.test.mjs`、`tests/graph-model.test.mjs`、`tests/bundle.test.mjs`、新增视图状态/过滤/探索单元测试与基准夹具；不引入 devDependencies。
- **宿主契约**：继续使用 `ctx.documentPreviews` + `sidebar.right.tab.document` 与可选 `ctx.betterSidebar`；不修改 DSH 核心或全局 profile，不改变插件安装方式。
- **依赖**：保持零运行时依赖；若 Worker 方案需要构建期内嵌源码，也只是复用现有源码字符串，不新增包。
- **明确不做**：不实现完整 RDF 1.1 / JSON-LD 1.1 / OWL 2 解析；不实现本体编辑、SPARQL、OWL 推理、跨文件图谱合并、源文件定位跳转；不做视觉体系重设计；不自动归档、不自动发版、不重装插件、不升级 V1.0.0。
- **兼容性**：对外没有编程 API；相对 IRI 的身份从"基于显示文件名的伪 `file:///` 地址"变为"基于真实资源地址或显式无 Base 降级"，属于**有意的行为更正**，会在变更说明中标注，不视为破坏性 API 变更。
